**Дата:** 2026-10-08 · **Статус:** всё готово и работает, обязательного ничего не осталось.

## 0. Что тут вообще происходит

Раньше DSH сам ходил в opencode.ai — медленно и с быстрым сжиганием лимитов.
Теперь всё идёт через маленькую программу **zen-router** (демон):

```
DSH (плагин dsh-opencode-zen)  →  127.0.0.1:8787 (zen-router)  →  opencode.ai
```

Демон держит тёплое соединение (быстрее), считает квоты, при лимитах переключает
IP (direct/WARP/другой ключ) — для этого нужен TUI и systemd-автозапуск.

## 2. Билд (собрать бинарь)

```sh
cd ~/Projects/zen-router
go build -o ~/.local/bin/zen-router ./cmd/zen-router
```
Собрал свежий бинарь на то же место. Если демон уже работает — чтобы подхватился
новый бинарь, перезапусти его (шаг 3).

**Важно: где какая копия бинаря**

| Путь | Что это |
|---|---|
| `~/.local/bin/zen-router` | **Главная рабочая версия.** Стоит в PATH, отсюда запущен демон и systemd-юнит. Именно её обновляет команда выше. |
| `~/Projects/zen-router/bin/zen-router` | Просто копия сборки внутри папки проекта (в `.gitignore`). Ей пользоваться не обязательно. Если она старая (собиралась давно) — в ней не будет `tui`. Пересобрать: `go build -o bin/zen-router ./cmd/zen-router` |

Проще всего: запускай `zen-router ...` **без `./`** из любой директории — это всегда
PATH-овая главная версия.

Проверить, что собралось без ошибок:
```sh
go build ./...
go vet ./...
```
Молчаливо отработали = всё ок.

## 3. Запуск демона

**Просто запустить (в фон):**
```sh
zen-router up --detach
```

**Или через systemd (настроено уже сейчас, автозапуск при входе в систему):**
```sh
zen-router install-systemd     # записать автозапуск (сделано один раз раньше)
systemctl --user status zen-router   # active = работает
```

Проверить, что живой:
```sh
zen-router status
```
Ожидаемо: `up: true`, режим `direct`, свой внешний IP.

`tail -f ~/.local/state/zen-router/zen.log` и `zen-router status`.

## 5. Панель управления (TUI)

```sh
zen-router tui
```
Клавиши: **r** — ротация IP, **d** — direct (напрямую), **w** — warp,
**s** — старт/стоп демона, **q** — выход.

Заметка: если запускаешь из скрипта/под `script`, нужен `TERM=xterm-256color`
и размер терминала, иначе экран пустой.

## 6. Остановить

```sh
zen-router stop
```
Юнит автозапуска тоже убрать, если совсем не нужно:
```sh
zen-router install-systemd --remove
```

## 10. Что осталось

**Обязательного — ничего.** Работает всё.

Нюансы (не сломано, просто так вышло в среде):
1. **WARP-ротация не может завершиться** — с этого компьютера не открывается
   `api.cloudflareclient.com` (таймаут). Код есть, тесты есть, но сети нет.
   Решение: как только появится доступ к этому адресу (VPN/другая сеть) —
   просто `zen-router use warp`.
2. **Во время ротации TUI пару секунд показывает «down»** — демон на этот момент
   держит замок на сетевом запросе, статус догоняет. Не критично.
3. **Мелочи из ревью (report-only)** — пара десятков мелких пунктов типа
   «уточнить формулировку в отчёте задачи» или «необязательный тест» — лежат в
   `docs/superpowers/ledger-plan2.md` и `ledger-plan3.md`, на работу не влияют.
